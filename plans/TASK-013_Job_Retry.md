# TASK-013: ジョブリトライ機能

## 1. タスク概要
ジョブが失敗した場合に、設定された回数まで自動的にリトライする機能を実装する。一時的なネットワーク障害やリソース競合による失敗を自動回復する。

## 2. 現状の課題
*   **現状:** ジョブが失敗した場合、即座に失敗として記録・通知される。リトライの仕組みがない。
*   **問題点:** 一時的な障害（ネットワークタイムアウト、ファイルロック等）で失敗した場合にも手動で再実行が必要。特にGit clone/pushのネットワーク依存処理は一時障害の影響を受けやすい。

## 3. 仕様・要件

### コアコンセプトへの適合
*   **Docker非依存:** 純粋なPythonロジック。
*   **容易な設定:** `config.yaml` にリトライ回数を1行追加するだけ。未設定時はリトライなし（従来動作）。

### 実装内容
*   **対象ファイル:**
    *   `src/core/config.py`: `retry_count`, `retry_delay` 設定の追加。
    *   `src/core/job_executor.py`: リトライループの実装。
    *   `src/core/notifier.py`: リトライ情報の通知メッセージへの付加。

### 設定ファイル
```yaml
jobs:
  - name: "Example"
    retry:
      max_attempts: 3      # 最大試行回数（デフォルト: 1 = リトライなし）
      delay_seconds: 10    # リトライ間の待機秒数（デフォルト: 10）
      # backoff_factor: 2  # 指数バックオフ倍率（将来拡張）
```

### 期待される挙動
1.  ジョブが失敗（非ゼロ終了コード）した場合、`max_attempts` に達するまでリトライする。
2.  リトライ前に `delay_seconds` 秒待機する。
3.  各試行のログは個別に記録し、何回目の試行かを明示する。
4.  最終的に成功した場合は成功として通知する（リトライ回数も含める）。
5.  全試行が失敗した場合のみ失敗として通知する。
6.  タイムアウト（`JobTimeoutError`）の場合はリトライしない（設定ミスの可能性が高いため）。

## 4. 優先度
**Low / Medium**
（運用安定性の向上に寄与。ネットワーク依存処理が多い環境で特に有効）
