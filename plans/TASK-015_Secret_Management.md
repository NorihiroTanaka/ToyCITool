# TASK-015: シークレット管理の強化

## 1. タスク概要
ジョブ実行時にシークレット（APIキー、パスワード等）を安全に注入する仕組みと、ログ出力時のシークレットマスキングを強化する。

## 2. 現状の課題
*   **現状:** シークレットは `.env` ファイルまたは `config.yaml` の環境変数展開で管理。ログのマスキングは `GIT_ACCESS_TOKEN` の単純な文字列置換のみ。
*   **問題点:**
    *   `config.yaml` にシークレットが平文で記載される可能性がある。
    *   ログへのシークレット漏洩対策が不十分（env経由で注入された値がスクリプトの標準出力に含まれた場合にマスクされない）。
    *   シークレットの種類が増えた場合にマスキング対象の管理が煩雑。

## 3. 仕様・要件

### コアコンセプトへの適合
*   **Docker非依存:** Python標準機能のみ。
*   **容易な設定:** シークレットとして扱う環境変数を `config.yaml` で宣言するだけ。

### 実装内容
*   **対象ファイル:**
    *   `src/core/config.py`: シークレット宣言の設定追加。
    *   `src/core/job_executor.py`: ログ出力時のマスキングフィルター強化。
    *   `src/core/logging_config.py`: ログフィルターとしてのマスキング処理追加。

### 設定ファイル
```yaml
jobs:
  - name: "Example"
    secrets:
      - DEPLOY_TOKEN       # 環境変数名を指定
      - DATABASE_PASSWORD
    env:
      DEPLOY_TOKEN: ${DEPLOY_TOKEN}
      DATABASE_PASSWORD: ${DB_PASS}
```

### 期待される挙動
1.  `secrets` に列挙された環境変数の値を、すべてのログ出力で `***` にマスキングする。
2.  マスキングは以下の箇所に適用する:
    *   ジョブスクリプトの標準出力/標準エラー出力。
    *   Python logging経由の全ログ。
    *   通知メッセージ（Discord/Slack等）。
3.  `config.yaml` 読み込み時のバリデーションで、`secrets` に指定された環境変数が未定義の場合は警告ログを出力する。
4.  `GIT_ACCESS_TOKEN` は暗黙的にシークレットとして扱う（宣言不要）。

## 4. 優先度
**Medium**
（セキュリティ対策として重要。外部サービスとの連携が増える段階で必須となる）
