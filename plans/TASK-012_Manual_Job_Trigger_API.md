# TASK-012: ジョブの手動実行API

## 1. タスク概要
Webhookを受信せずに、API経由で任意のジョブを手動トリガーできるエンドポイントを実装する。

## 2. 現状の課題
*   **現状:** ジョブの実行にはGitサーバーからのWebhookが必須。手動でジョブを再実行する手段がない。
*   **問題点:** テスト・デバッグ時にわざわざGitにpushする必要がある。一時的なネットワーク障害等でWebhookが届かなかった場合の再実行手段がない。

## 3. 仕様・要件

### コアコンセプトへの適合
*   **Docker非依存:** FastAPIエンドポイントの追加のみ。
*   **容易な設定:** 設定不要。APIを呼ぶだけ。

### 実装内容
*   **対象ファイル:**
    *   `src/api.py`: 手動トリガーエンドポイントの追加。
    *   `src/core/job_service.py`: Webhook経由でないジョブ実行パスの追加。

### エンドポイント

#### `POST /api/jobs/{job_name}/trigger`
```json
{
  "branch": "main",
  "commit": "abc1234"
}
```
*   `branch`: 対象ブランチ（省略時はデフォルトブランチ）。
*   `commit`: 対象コミット（省略時は最新コミット）。

#### レスポンス
```json
{
  "job_id": "uuid-here",
  "status": "queued",
  "message": "ジョブ 'Example' をキューに追加しました"
}
```

### 期待される挙動
1.  指定されたジョブ名が `config.yaml` に存在するか検証する。
2.  存在する場合、ジョブをキューに追加し、即座にレスポンスを返す（非同期実行）。
3.  ジョブ名が不明な場合は `404 Not Found` を返す。
4.  TASK-007の署名検証が有効な場合、手動トリガーAPIにも認証を適用する（APIキーまたはBearer Token）。
